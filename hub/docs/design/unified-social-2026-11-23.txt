SlipSurge unified experience: social implementation handoff
23 November 2026

Purpose and direction
Member conversations should feel like the same SlipSurge workspace as navigation and research. Visitors can read genuinely public content before an account prompt; joining, posting, following and private conversations still require their existing account/access checks.
Use the approved Geist typeface, semantic light/dark surfaces, restrained lime for primary actions and existing member identity art. No changes to sports boards, logos, headshots, odds, scores, models or formulas. ENERGY 2 / RHYTHM 2 / MOTION 1.

Implemented
1. Remove the duplicate four-link CommunityNav row from root social pages. Messages and Live rooms now have the same labeled More menu as Communities. The menu keeps Live rooms, Messages, Saved posts, Activity, Discussions, Pages, Events and Articles reachable. Nested pages return to their actual area; group settings returns to the community.
2. Inbox tabs have a single keyboard tab stop, Arrow/Home/End operation and matching tab/panel labels. Accept/decline waits for server acknowledgement, prevents overlapping actions, handles rejected promises and returned errors, and keeps failed requests available for retry.
3. Pick/Poll composer modes preserve staged selections and field values while switching or closing a builder. Closing a builder returns the selected mode to Take. Wager has a programmatically associated label. Post-type tabs now have keyboard operation and a named panel.
4. Anonymous Feed, ProfilePostList and GroupPostFeed never auto-fetch protected pagination APIs. Public previews do not falsely end with "You're all caught up". Members retain their full pagination paths.
5. Public Feed has an optional account prompt, specific Following opt-in and no signed-in saved-research header controls. Public/free group guests see metadata plus a join prompt and public Feed link, without an empty restricted posts panel. Private/paid content is not exposed.
6. Community discovery shows actual filtered collection counts and a working clear-filters action. Guest Your communities has a specific opt-in; discover remains available. Storefront card headings can be h3 below an existing h2 without changing other pages.
7. Live rooms distinguishes membership access from a genuinely empty set of rooms, while retaining its Basic-tier checks. Its fallback offers communities and plans rather than falsely saying rooms do not exist.

Evidence boundaries and parent integration checks
The component tests render real changed components in JSDOM with isolated auth/data and adjacent visual primitives. They certify state transitions, retries, draft retention and semantics, not browser layout or backend availability. Anonymous pagination page expressions are source contracts; middleware/RLS checks are owned by the integrating agent.
Parent must complete the optimized build/typecheck and actual in-app browser checks in light/dark at phone, tablet and desktop widths before release. This is an implementation handoff, not a production delivery receipt.
