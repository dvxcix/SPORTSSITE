Changes
- Set up, Member preview and Access rules are separate views within the existing community Discord tab and group settings.
- Account authorization leads first-time setup; bot installation is scoped to the selected managed server. Empty managed-server results explain permission requirements and provide a real retry.
- Selecting or reopening a saved server automatically inspects its bot permissions and roles. Returning from an intentional bot installation triggers one fresh check, with no polling. Refresh remains available.
- Server checks cancel when selection changes. A delayed response cannot populate another server's editor. Clearing selection cannot leave a connected checkpoint or a usable save action behind.
- Manage Roles is verified on the actual bot before offering roles or role creation. Hierarchy recovery explains the exact Discord settings path and retains a permission-review link.
- Saved roles are separate from unsaved selections. Preview uses the real member card summary component and only saved configuration. It does not claim or grant roles. Actual community entry remains accessible.
- Access rules shows the owned community and its bound membership title from server data. Product lookup is restricted to the same creator. The view explains eligibility, expiry, removal and old-account cleanup; other server roles are untouched.
- Connect-panel publication is disabled for unsaved settings. Existing claims, private commands, provider verification, prioritised removals and legacy SlipSurge-server automation remain in place.
